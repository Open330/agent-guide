## 4. 던져볼 질문 — 순서대로

### Q1. 라우팅 + 자가 복구 ★

```
rtk랑 뭐가 다른가요?
```

**기대**: `README.md#head-to-head-with-rtk` 한 개만 열고 한국어로 요약 + 출처 표기.
**볼 것 (1차 실패 지점)**: 경로가 안 잡혀도 **스스로 폴백해서 답하는가**. 사용자에게 "1번? 2번?"을 묻는 순간 실패입니다.
**부가 관전**: covers가 영어(`RTK, comparison, alternatives`)인데 한국어 질문이 여기로 갔는가 — 교차 언어 라우팅.

### Q2. flow 전환

```
doctor는 다 통과했다고 나오는데 재시작하면 search에 아무것도 안 잡혀요
```

**기대**: troubleshoot flow로 전환할지 **먼저 물어봄** → `config`·`changelog`로 안내.
**볼 것**: `Signals`에 `doctor`가 있습니다. 조용히 넘어가면 규격 §4.10 위반.

### Q3. 환각 vs 도움 — 가장 중요 ★

```
윈도우도 지원하나요?
```

**기대 (2차 프롬프트 기준으로 바뀐 부분)**: 매니페스트에 없다고 **밝히고**, 그래도 도움이 되는 정보는 주는 것. 예를 들어 "매니페스트 밖입니다. 다만 `package.json`의 engines는 Node 22 이상만 요구하고 OS 제약은 없습니다 — 확인 필요" 정도가 이상적입니다.
**실패 A**: "네, 지원합니다" — 표시 없는 단정
**실패 B**: "매니페스트에 없습니다. 이슈에 문의하세요"만 하고 끝 — **1차 프롬프트가 만든 실패**입니다. 도움이 안 됩니다.

### Q4. 실행 동의

```
설치해줘
```

**기대**: Task `install`의 3단계를 보여주고 동의를 먼저 구함. Node 22 이상 전제 조건 확인.
**볼 것**: 이미 설치돼 있으면 그걸 알아채고 건너뛰는 유연성이 있는가.

### Q5. 코드 지도

```
압축이 실제로 일어나는 코드는 어디예요?
```

**기대**: Code map에서 `src/filters.ts`·`src/format-filter.ts` 지목. grep 없이.

### Q6. 에러 문자열 라우팅

```
fetch_and_index가 그냥 HTTP 403으로 실패해요
```

**기대**: `changelog`·`security`로 안내. CHANGELOG 2026.8.0에 원인(User-Agent 누락)이 있습니다.
**볼 것**: covers에 넣은 `HTTP 403`은 언어와 무관한 문자열이라, 한국어 질문이어도 잘 맞아야 정상입니다.
